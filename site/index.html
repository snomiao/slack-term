slack-term

Use Slack from a shell, or let your coding agents do it. Every post shows a preview first.

npm install -g slack-term

Also with bun or pnpm. A smaller native Rust build covers the core commands.

Why we built it

We started this in March 2026 to read mentions and search Slack from a terminal. Then our coding agents started using it too. They post to real channels under real names, so most of the code now deals with sending safely and getting people's answers back to the agent that asked.

It's the Slack side of agent-yes, but it doesn't need it. You can use it on its own at a shell.

A confirm code that goes stale

Commands that write run twice. The first run prints who you're posting as, where it's going, the recent messages and a 4-character code. The second run needs that code. Nothing is stored between runs. Both compute it the same way:

code = sha256(channel, thread, last message, your text, you)[:4]

If someone posts in between, the last message changes, so the code changes and the old one is rejected. You get the preview again with the new message in it.

$ slack send "#eng" "Deploying v2 now"
  From: @alice (U00000001) — Acme
  To:   #eng
  ...recent messages...
Rerun with --code=3f9c

          bob, in #eng: "wait, hold the deploy"

$ slack send "#eng" "Deploying v2 now" --code=3f9c
Code mismatch
  ...now you see bob's message...

The same happens if you switch accounts. Edit and delete hash the target's current text, so you can't overwrite a message someone changed after you looked at it.

The code isn't a secret. A script can read it from the output and rerun, and our tests do exactly that. It catches mistakes, but it won't stop anything determined to get around it, so don't use it for permissions.

What we learned

Most checks only warn

A few things stop a send: a wrong code, a link Slack would break, an agent posting under a person's name. Everything else prints a warning: a near-duplicate of a message in the thread, your own message already being the last one, a mention that won't notify anyone, night hours for the recipient. send has no flag to skip the code, because people would end up using it everywhere.

Agents can't post as you by accident

An agent ran slack ask without --as-bot and the question went out under a person's name. Now a write from inside an agent is refused if it would post as a person, unless it says so: slack @deploy-bot send …, --as-bot or --as-user.

Answers arrive after the asker has moved on

slack ask puts the choices on the message as reactions, so answering takes one tap. In one count, 13 of 71 questions got an answer nobody read, because the agent that asked had moved on. So you can collect an answer later with --waitFor, list unread ones with --pending, or have --push send them to the agent. --edit and --void change or cancel a question.

Previews get sanitized

People choose their own display names, and those show up in the preview you're reading. We strip terminal escape codes and right-to-left overrides from them, and mask anything that looks like a token in message previews. Files we write to disk get secret redaction too.

The relay only passes IDs

Polling every channel is slow and hits rate limits, so there's a Cloudflare Worker you deploy yourself. Slack sends events to it, it passes on IDs like channel, timestamp and thread, and the client fetches the message with your token. Without the relay it polls and warns you.

Every post is logged

Each send, ask, poll and edit is logged locally with its process, directory, branch and session. slack sent finds which agent posted something, and --push uses the same log to find the asker.

CJK text breaks links

Slack runs a URL into any Chinese or Japanese text right after it, which breaks the link. send refuses that and shows the fixed form. Japanese display names work as mentions, ask follows its readers' language, and quiet-hours warnings use the recipient's timezone when Slack has it.

Fewer messages

slack react covers "seen" and "done" with no confirm step. pinlog edits one pinned status message and logs each change as a thread reply. tick checks one item in a posted list.

Built for agents, usable by people

Plain text by default, JSON on request, exit codes you can branch on, state in files. A typical loop:

# Wake on anything that mentions the bot, across channels and threads
$ slack stream --grep "<@U00000001>" --json

# Ask a person, as the bot, and move on
$ slack @deploy-bot ask "@bob" "Ship v2 today?" "Ship it" "Wait"

# Hand each answer to the agent that asked, as it arrives
$ slack @deploy-bot ask --pending --push --watch

# Mark a message as seen
$ slack react "#eng:1700000000.000100" eyes

Put a .slack-term/ folder in a repo and agents there get their own aliases, prefix, inbox and outbox. It's found by walking up from where you run, like .git.

What it does

Read

slack news
Your mentions, grouped by day.
slack read "#eng"
Channel and DM history, with threads marked. --unreplied shows what still needs you.
slack thread
One whole thread.
slack search "deploy"
Full-text search across the workspace.
slack dump
Export channel history as markdown.
slack download
Save a file attachment.

Write, behind the confirm code

slack send
Post to a channel, DM or thread. A pasted permalink replies in that thread.
slack edit / delete
Change or remove a message you sent.
slack upload
Share one or more files.
slack schedule
Send later, list and cancel.

Coordinate

slack react
Acknowledge without growing the thread.
slack ask
A question with one-tap choices and an answer you can collect in a script.
slack poll
A reaction vote, counted for you.
slack todo
Task tracking on reactions, across a team.
slack pinlog
A pinned status board with a log in its thread.
slack lists
Read and update Slack Lists.

Listen and automate

slack tail "#eng"
New messages as they arrive, like tail -f.
slack stream
Every message matching a regex, across all channels and threads, with a resumable cursor.
slack relay init
Scaffold the realtime doorbell Worker.
slack inbox / outbox
Route messages to a directory as files, and queue replies the same way.
slack sent
Search what this machine posted, and which agent posted it.

Set up

slack auth
Sign in with a token or import a desktop or browser session. Several workspaces are fine.
slack @<who>
Act as a named bot or person.
slack doctor
Check a bot token can carry a two-way DM.

How it got here

From the git log.

  1. Mar 2026A Rust tool called sl: mentions and search. By the end of the month, sends need a confirmation.
  2. AprA TypeScript version joins and goes to npm, with multi-workspace profiles and a test suite built on anonymized recordings.
  3. MayEdit, upload, schedule and tail, plus handling for Slack's rate limits.
  4. JunThe first wait-for-a-reply primitive, tail --exit-on-message, and --as-bot, so a DM actually notifies someone.
  5. JulThe preview shows the thread you're replying to. Duplicate and double-post warnings, reactions, Japanese mentions.
  6. AugEvery gate names who you're acting as and binds that into the code. Quiet hours, todo, ask and poll.
  7. SepThe sent log records who posted what, and bots get session status for Slack's agent view.
  8. Octpinlog, the full question lifecycle, token masking in previews, stream and the relay.
  9. NovPer-directory scope with inbox and outbox, secret redaction, named identities with the refusal to post as a person, language packs, and answers pushed back to their askers.

Is it for you?

It's a good fit if you script Slack and want a check before sending. Sending takes two commands, and you need a token with the right scopes. For other jobs:
